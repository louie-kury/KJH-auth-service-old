# MySQL 계정·로그인 저장 기반 — 실행 계획서

- 이슈: [인증 서비스 #3](https://github.com/louie-kury/louie-kury-auth-service/issues/3)
- 브랜치: `feat/3-mysql-account-login`. 커밋은 매번 사용자 승인 후 진행한다.

## 범위와 진행 상태

계정·로그인 JPA 매핑과 저장 기반을 구성한다. 기존 `svc_identity` DB의 `account`, `login_credential` 테이블·인덱스·외래 키는 읽기 전용 조회로 확인했고, JPA 매핑과 저장소는 커밋했다. 두 정보의 트랜잭션 저장 및 비밀번호 해시 코드는 작업 중이다. 실제 기존 테이블을 다시 생성하거나 변경하는 계획은 없다.

이메일 인증, 가입·로그인 API와 토큰, MongoDB 프로필, 소셜 인증은 후속 작업이다. Refresh token의 설계와 적용 시점은 추후 결정한다.

## 이번 작업의 결정

- 최신 ERD의 `login_credential.account_id` 외래 키와 `login_id` UNIQUE를 유지한다. 로그인 ID 검색용 HMAC 컬럼이나 인덱스를 추가하지 않는다. [인증 ERD](../../../../louie-kury-document/docs/erd/svc_identity.md)
- 사용자가 개인정보를 최신 ERD의 컬럼 형식으로 저장하도록 지정했다. 이는 공통 PRD의 개인정보 암호화 요구와 다르며, 공통 문서 변경은 보류 중이다. 비밀번호는 별도로 hash만 저장한다. [PRD](../../../../louie-kury-document/docs/prd.md#61-보호자-계정--acc)
- 이메일은 앞뒤 공백을 제거하고 원래 대소문자를 보존해 저장한다. 전체 이메일의 대소문자 차이는 중복으로 취급한다. 실제 `email` 컬레이션 `utf8mb4_0900_ai_ci`는 악센트 차이도 구분하지 않는다. 이는 로컬 부분의 대소문자를 구분하는 현재 공통 API 문서와 다르다. [인증 API](../../../../louie-kury-document/docs/api/auth.md#이메일-인증과-일반-가입)
- 새 비밀번호는 `DelegatingPasswordEncoder`를 통해 `{argon2id}` 식별자와 함께 Argon2id로 저장한다. 시작 설정은 메모리 19,456 KiB, 반복 2회, 병렬도 1이며 배포 환경에서 비용을 측정한다. Bouncy Castle을 사용한다.
- 사용자가 승인한 정책은 비밀번호 최소 15자, 최대 64자 이상, 문자 종류 강제 없이 공백·붙여넣기 허용이다. 구현 시 최대 128 Unicode 코드 포인트는 제안값으로 기록하며 최종 구현과 일치 여부를 확인한다. 길이 검사 후 입력을 변형하지 않고 해시한다. 자주 사용되거나 유출된 비밀번호 차단은 적용 시점과 검사 방법이 남아 있다.
- 계정과 로그인 정보를 함께 저장할 때는 하나의 MySQL 트랜잭션을 사용한다. 가입 완료와 프로필 저장 상태 전이는 후속 가입 API 작업이다.

## 공통 문서와 정합성

공통 PRD·API에는 여전히 개인정보 암호화, 비밀번호 8~20자 및 영문·숫자·특수문자 강제, 이메일 로컬 부분 대소문자 구분이 기록돼 있다. 사용자는 현재 공통 문서 수정을 보류했다. 이후 공통 문서 정리 시 위 결정을 대조한다. 로그인 ID HMAC UNIQUE도 사용자 지시에 따라 현재 ERD의 `login_id` UNIQUE로 조정했다.

## 검증과 남은 확인

- 계정·로그인 매핑은 격리 MySQL에서 저장·조회, 감사 시각, UNIQUE 및 외래 키를 확인했다. 현재 작업의 Argon2 전환 후 테스트 결과는 별도로 기록한다.
- 새 hash의 식별자와 파라미터, 같은 입력에 서로 다른 salt, 올바른 비밀번호와 잘못된 비밀번호 검증, 저장 컬럼 길이 및 비밀번호 길이 경계를 확인한다.
- 격리 MySQL에서 계정·로그인 원자 저장과 실패 시 롤백, 이메일 대소문자 중복 차단을 확인한다. 실제 기존 DB는 읽기 전용으로 사용한다.
- 이메일 컬레이션의 악센트 비구분과 로그인 ID 비교 기준, 성별·상세 주소 및 약관 동의 저장 방식은 후속 정책과 대조한다. 로그인 API가 구현될 때 이전 해시 이관 여부와 검증·재해싱 경로를 확인한다.
